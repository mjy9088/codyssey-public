# Mini NPU Simulator

숫자 행렬의 MAC(Multiply-Accumulate) 점수를 직접 계산하여 Cross와 X 패턴을 판별하는 Python 콘솔 애플리케이션입니다. Python 3.8 이상과 표준 라이브러리만 사용합니다.

## 실행 방법

```bash
mise install
just run
```

실행 후 `1`은 3×3 사용자 입력 모드, `2`는 현재 디렉터리의 `data.json` 일괄 분석 모드입니다. 입력 모드에서는 필터 A 3행, 필터 B 3행, 패턴 3행을 차례로 입력하며 각 행은 공백으로 구분한 숫자 3개여야 합니다. 잘못된 행은 오류 메시지 후 해당 행을 다시 입력합니다.

테스트는 다음 명령으로 실행합니다.

```bash
just test
just check
```

`just analyze`는 별도 입력 없이 번들된 JSON 분석 모드를 실행하고, `just demo`는 과제의 3×3 예제 입력을 재현합니다. `just`를 사용할 수 없는 환경에서는 `python3 main.py`와 `python3 -m unittest discover -s tests -v`를 직접 실행할 수 있습니다. 별도의 셸 스크립트는 필요하지 않으며, 이후 추가할 경우 Git 실행 권한에 기대지 않고 `sh path/to/script.sh` 형태로 호출합니다.

## 구현 요약

`mac()`은 중첩 반복문으로 같은 위치의 원소를 곱해 누적합니다. NumPy 등 외부 라이브러리는 사용하지 않습니다. `validate_matrix()`가 행·열 크기 및 수치 타입을 검사하고, JSON 분석 중 발생한 데이터 오류는 케이스별 FAIL로 격리합니다. 패턴 키 `size_{N}_{idx}`에서 N을 읽어 같은 크기의 필터를 선택합니다.

필터 키 `cross`, `x`와 expected 값 `+`, `x`는 내부 표준 라벨 `Cross`, `X`로 정규화합니다. 두 점수 차가 `1e-9` 미만이면 부동소수점 표현 차이로 순위가 뒤집히지 않도록 `UNDECIDED`로 판정합니다. 성능 측정은 파일 읽기와 출력을 제외한 MAC 호출만 크기별 10회 반복하고 평균 ms와 N²을 표시합니다. 실제 시간은 하드웨어, Python 버전, 시스템 부하에 따라 달라집니다.

## data.json 스키마

```json
{
  "filters": {
    "size_5": {"cross": [[0]], "x": [[0]]},
    "size_13": {"cross": [[0]], "x": [[0]]},
    "size_25": {"cross": [[0]], "x": [[0]]}
  },
  "patterns": {
    "size_5_1": {"input": [[0]], "expected": "+"}
  }
}
```

위 행렬 표기는 구조 설명을 위해 축약한 것입니다. 실제 파일은 각 size에 맞는 N×N 수치 배열이어야 합니다.

## 결과 리포트

1. 제공한 `data.json`의 정상 케이스는 필터와 같은 패턴을 사용하므로 모두 PASS한다.
2. `+`와 `cross`가 모두 `Cross`로 정규화되므로 표기법 차이가 거짓 FAIL을 만들지 않는다.
3. 대소문자와 앞뒤 공백도 정규화 단계에서 통일된다.
4. 알 수 없는 라벨은 임의로 추측하지 않고 해당 케이스의 명확한 FAIL 사유가 된다.
5. 필터 누락이나 N×N 크기 불일치는 데이터·스키마 문제로 분류할 수 있는 메시지를 남긴다.
6. 정상 크기인데 오답이 나오면 MAC 구현 또는 필터·패턴 값 자체를 우선 점검해야 한다.
7. 거의 같은 실수 점수는 `abs(a-b) < 1e-9`일 때 동점 처리하여 미세한 표현 오차를 제거한다.
8. 이 정책으로 나온 `UNDECIDED`가 expected Cross/X와 비교되면 의도대로 FAIL하며 이유가 요약된다.
9. MAC은 N개 행의 N개 열을 한 번씩 방문하므로 원소별 곱셈 횟수는 정확히 N²이다.
10. 따라서 입력 한 건의 시간 복잡도는 O(N²), 별도 결과 행렬을 만들지 않아 추가 공간 복잡도는 O(1)이다.
11. 3, 5, 13, 25 크기의 연산 횟수는 각각 9, 25, 169, 625로 증가한다.
12. 평균 시간도 대체로 N² 증가를 따르지만 매우 짧은 측정에서는 타이머와 시스템 잡음의 영향이 있다.
13. 반복 10회 평균은 단일 측정보다 잡음을 줄이지만 정밀 벤치마크를 뜻하지는 않는다.
14. 실패 진단 순서는 스키마/라벨, 행렬 크기, 계산 로직, epsilon 비교 정책 순으로 분리하는 것이 효과적이다.
