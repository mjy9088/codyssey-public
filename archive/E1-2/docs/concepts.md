# 처음 보는 사람을 위한 핵심 개념

## 가상환경은 왜 필요한가?

가상환경(`.venv`)은 이 프로젝트가 사용할 Python 실행 환경을 다른 프로젝트와 분리합니다. 이 프로젝트에는 외부 패키지가 없지만, 같은 Python과 import 경로로 실행·테스트했다는 점을 보장할 수 있습니다.

`scripts/setup_venv.sh`는 다음 두 작업을 합니다.

1. `python -m venv`로 `.venv`를 만듭니다.
2. `.pth` 파일로 `quiz_game/src`를 가상환경의 모듈 검색 경로에 추가합니다.

`.pth`는 Python이 시작할 때 읽는 작은 경로 파일입니다. 그래서 소스 코드를 복사하거나 시스템 Python을 변경하지 않고 `import quiz_game`을 사용할 수 있습니다.

## `src` 폴더는 왜 한 단계 더 있는가?

```text
quiz_game/
├── src/quiz_game/  # 실행할 패키지
└── tests/          # 패키지를 사용하는 테스트
```

실행 코드와 테스트를 분리하면 테스트가 우연히 현재 디렉터리의 파일을 가져오는 실수를 줄일 수 있습니다. 테스트는 가상환경에 연결된 패키지를 실제 사용자처럼 import합니다.

## 클래스는 어떻게 역할을 나누는가?

- `Quiz`: 문제 한 개와 정답 판정
- `QuizSession`: 퀴즈 한 판의 진행 상태
- `ScoreRecord`: 점수와 최고 기록 비교
- `GameState`: 파일에 보존할 퀴즈와 최고 점수
- `QuizGame`: 퀴즈 추가, 게임 완료와 변경 여부 관리
- `ConsoleUI`: `input()`과 `print()`

이렇게 나누면 점수 계산을 테스트할 때 키보드 입력이나 JSON 파일이 필요하지 않습니다.

## 직렬화는 무엇인가?

직렬화는 Python 객체를 JSON에 저장할 수 있는 문자열, 숫자, 목록과 딕셔너리로 바꾸는 과정입니다.

```text
GameState ──to_data()──> dict ──json.dump──> state.json
GameState <─from_data── dict <──json.load─── state.json
```

모델은 파일 경로나 JSON 모듈을 모르고 데이터 형태만 변환합니다. 실제 파일 읽기와 쓰기는 `storage.py`가 담당합니다.

## 임시 파일은 왜 사용하는가?

`state.json`을 바로 쓰다가 프로그램이 중단되면 기존 파일까지 손상될 수 있습니다. 먼저 `state.json.tmp`를 완성하고 마지막에 원본 이름으로 교체하면, 쓰기 도중 실패해도 기존 상태가 남습니다.

이미 손상된 파일은 자동으로 덮어쓰지 않고 `state.json.broken`으로 옮겨 복구 가능성을 남깁니다.

## 미저장 변경은 왜 추적하는가?

퀴즈를 추가하거나 최고 점수가 바뀌면 `QuizGame.has_unsaved_changes`가 참이 됩니다. 저장에 성공했을 때만 다시 거짓으로 바뀝니다. 저장이 한 번 실패해도 프로그램 종료 직전에 재시도하기 위한 표시입니다.

## Docker 검증은 무엇을 보장하는가?

- GitHub 실습은 과제 요구대로 실제 origin에서 clone·push·pull 흐름을 수행합니다.
- 공개 origin 검증은 호스트 파일을 마운트하지 않은 새 컨테이너에서 수행합니다.
- `env -i`는 컨테이너 이미지의 환경변수도 비우므로 호스트나 이미지에 있던 인증 정보가 우연히 사용되는 일을 막습니다.

Docker는 매번 같은 서버와 Git 클라이언트 환경을 만들기 때문에 개인 컴퓨터 설정에 덜 의존하는 증거가 됩니다.

## PTY 증거는 일반 로그와 무엇이 다른가?

PTY는 터미널 프로그램이 실제 사용자와 대화할 때 사용하는 입출력 장치입니다. 증거 생성기는 프롬프트가 나타난 것을 확인한 뒤 답을 입력하고, 그 순서와 출력을 `.cast`에 기록합니다. 미리 준비한 텍스트를 단순히 출력하는 것보다 실제 콘솔 프로그램이 동작했다는 근거가 강합니다.
